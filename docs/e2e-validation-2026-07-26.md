# SKU 采集端到端验证报告（2026-07-26）

## 结论

OpenCLI 可以采集目标 JSON，但当前“逐 SKU 打开京东商品页并捕获接口响应”的方案不能稳定满足
每天 10,000 个 SKU。主要限制不是本地吞吐，而是京东 PC 商品页频控。

## 数据与环境

- 输入：`wx.cj.csv`
- CSV 数据行：239
- 京东 SKU：221 个，均唯一
- 淘宝商品：18 个，已按 `platform=jd` 排除
- OpenCLI：1.7.14
- Browser Bridge 扩展：1.0.5
- 验证浏览器：独立临时 Edge profile
- 并发：1 个 profile

## 单条验证

SKU `100102037778` 成功：

- 输出大小：65,091 字节
- 顶层字段：`商品ID`、`商品名称`、`商品平台`、`商品链接`、`采集时间`、`详情数据`
- `详情数据` 字段数：56
- 响应 `pageConfigVO.skuid` 与输入一致
- 商品标题正确

验证输出位于本地 `data/e2e-single/`，该目录属于运行产物，不进入版本控制。

## 连续 30 条验证

- 总耗时：673.287 秒
- 成功：14
- 失败：16
- 成功率：46.67%
- 成功文件平均大小：54,049 字节
- 成功文件范围：29,796–74,149 字节
- 第 16 条开始出现连续失败
- 最终浏览器地址：
  `https://pc-frequent-pro.pf.jd.com/?from=pc_item&reason=403`
- 页面标题：`PC频控页 -京东商城`

失败记录位于本地 `data/e2e-batch30/errors.jsonl`，统计结论保留在本文档中。

## 容量判断

本次平均处理时间约 22.44 秒/输入（包含失败重试）。即使忽略频控，单 profile 按这个速度完成
10,000 条也需要约 62.3 小时。增加 profile 可以提高本地并行度，但多个 profile 共享同一公网出口，
不能解决此次实测到的 PC 页面频控，因此不能据此承诺日采 10,000。

## 建议

1. 生产需求优先申请京东开放平台/JOS 商品接口或获得平台授权的数据服务。
2. OpenCLI 保留为小批量验证、字段补全和故障回退通道，不作为 10,000/日的主采集链路。
3. 若继续评估浏览器链路，必须先增加频控熔断和长时间冷却，再以平台允许的频率测试；不要通过简单增加
   profile 绕过平台限制。
